## 노트북 `assets/fire-bias.ipynb` (교과서 소스 노트북 214~216쪽 부분 + 준비 셀)
- **준비 셀 하나**: zip 내려받기 → 라이브러리 → `path`·`train_fire`·`train_non_fire` → 컬러 데이터 설정 → 컬러 CNN(교과서 209쪽 코드) → compile → fit 8. 「산불 이미지 분류」 노트북에서 한 일을 한 번에 다시 함(코랩은 창을 닫으면 모델이 사라짐).
- 214쪽 test3: `files.upload()` 대신 `path + '/test3.jpg'`, `/ 255`, `classes3[0][0] < 0.5`(u4-unstructured-1 DESIGN의 오류 5와 같은 이유).
- 215쪽 `read_img` GRAY + 회색조 사진 보기(`cmap = 'gray'` 더함 — 교과서 그림은 이 옵션이 없어 초록·보라 색으로 보임).
- **회색조로 학습하는 셀(교과서와 다른 부분)**: `flow_from_directory(..., color_mode = 'grayscale')`, `gray_model`의 `input_shape = (400, 400, 1)`, 테스트 사진 `img3.convert('L')`.
- 216쪽 `gray_model.fit(..., epochs = 15)`, 예측은 `classes4`로 출력.
- (선택) test1·2·3을 컬러 모델·회색조 모델로 비교하는 셀.

## 교과서 오류·모호한 곳과 처리
1. **회색조 학습이 실제로는 일어나지 않음(215~216쪽, 소스 노트북)** — 바꾼 `read_img`는 `plt.imshow`로 사진을 보여 줄 때만 쓰이고, 학습 데이터는 `flow_from_directory`가 기본값 `color_mode='rgb'`로 다시 읽음. `gray_model`도 `input_shape=(400, 400, 3)`. 소스 노트북 summary가 컬러 모델과 똑같이 Total 9,451,777인 것으로 확인됨(회색조라면 첫 층 160, 합계 9,451,489). 즉 교과서의 gray_model은 컬러 사진으로 15 에포크 더 학습한 모델. → 화면 03 「read_img만 바꾸면 학습 데이터는 그대로예요」 상자와 노트북 셀로 바로잡음. 테스트 사진도 회색조로 바꿔야 함(교과서는 컬러 `images3`를 그대로 넣음).
2. **216쪽 마지막 셀이 `classes4`를 만들고 `classes2`를 출력** — `classes2`는 213쪽 test2(숲 사진) 결과라 늘 [1.] Non_Fire Image. 교과서 결과 「[1.] Non_Fire Image」는 빨간 건물의 결과가 아님. → 노트북은 `classes4`로, 화면에 「교과서에는 classes2로 잘못 적혀 있어요」.
3. 1·2 때문에 교과서는 「회색조로 바꾸었더니 빨간 건물을 산불이 아닌 이미지로 인식」을 실제로 보여 준 것이 아님. 화면 04는 교과서 결과를 소개하되 「내 노트북 결과는 다를 수 있어요」 + 내 결과 투표 + 「회색조가 늘 해결해 주는 것은 아님 → 붉지만 산불이 아닌 사진(단풍·노을·빨간 건물)을 non에 더하는 것이 근본적인 방법(지도서 「다양한 데이터를 수집하여 균형 잡힌 데이터셋」)」으로 정리. 학습 결과를 이 컴퓨터에서 돌려 확인하지는 못함.
4. 214쪽 test3 정규화 빠짐 — u4-unstructured-1 DESIGN 오류 5와 같음(`/ 255` + 0.5 기준).
5. 215쪽 「흑백」·「회색조」·「GRAY」 섞어 씀 → 화면은 「회색조(흑백)」로 통일.
6. 216쪽 「편향된 데이터로 성능 평가하기」라는 제목은 실제로는 「회색조로 다시 학습해 평가하기」 → 화면 제목은 「다시 학습하고 평가하기」, 머리에 교과서 소제목 표기.
7. 215쪽 「모델의 학습 속도도 향상」 — 첫 합성곱층 매개 변수만 448 → 160으로 줄고 전체(약 945만 개)는 거의 같음. 사진을 읽고 옮기는 양이 1/3이 되는 효과 → 화면에 숫자와 함께 「조금」으로 표현.

## 지어낸 것·계산한 것(표시함)
- **붉은 픽셀 비율**: 모델이 보는 400×400 크기(학습 사진은 원래 크기, test1~3은 400×400으로 줄여서)에서 HSV 색상 0~40°·340~360°, 채도 > 0.45, 명도 > 0.35인 픽셀의 비율(%) — zip의 JPEG 324장과 test1~3으로 파이썬에서 계산(검토 반영으로 100×100 계산에서 바꿈). 결과: 산불 아님 162장 중 105장이 0%, test1 35.6% · test2 4.9% · test3(빨간 건물) **46.7%**(산불 사진 162장 중 129장보다 붉음). 「붉은 비율 ≥ 5% → 산불」 규칙만으로 학습 데이터 86.7%를 맞힘, 빨간 건물을 산불이 아니라고 하려면 기준을 48% 이상으로 올려야 하고 그때 정확도 59.3%. 화면에 「CNN이 실제로 이 규칙을 쓴다는 뜻은 아니고, 데이터만으로도 색이라는 지름길이 이만큼 통한다」고 밝힘.
- 셀 흉내의 확률·학습 기록 숫자는 예시(컬러 8 에포크는 교과서 소스 노트북의 실제 기록).
- 분류 게임 7장(편향을 줄이는 데이터 / 줄이지 못하는 데이터)은 지도서 「다양한 데이터를 수집하여 균형 잡힌 데이터셋」과 214쪽 정의에서 만든 예시.
