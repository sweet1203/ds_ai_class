쓰기 메모 4칸(`naChoice`·`outlierCheck`·`keyAttr`·`tipsCause`) + 투표 3개 + 칩 1개. 퀴즈 11문항(05 tips는 퀴즈 없음). 질문폼 1번 ← 01 실험실(30행 범위에서 (다)를 고르면 세토사가 10개→5개)·`naChoice`, 2번 ← 03 박스 플롯 161번·02 탐색기·`outlierCheck`, 3번 ← 04 산점도·`keyAttr`.

**50분 흐름** — 도입(2분) 투표 → 01(10분) isna, 세 방법을 두 데이터 범위에서 비교, 메모 → 02(7분) describe 해석, 탐색기로 69쪽 스스로 해결하기 → 03(11분) IQR 계산 따라가기, 161번 점 끌어 보기, 메모 → 04(9분) 산점도 6쌍 비교·투표, 히트맵, 메모, 개념 빈칸(여기까지 약 40분 — 수업의 중심이 끝남) → 마무리(6~8분) 퀴즈 결과·질문폼 → 05 tips는 **선택 · 과제**(시간이 남으면 예상 투표만 함께, 나머지는 과제).

**줄인 것** — 코드는 노트북(교과서 소스 파일 사본)으로 실행할 수 있게 두고, 화면에는 핵심 코드와 실행 결과(교과서 출력값)를 보여 줘 실행하지 않아도 따라오게 함. 히스토그램·박스 플롯·산점도·히트맵은 같은 데이터로 SVG를 다시 그림(모양은 seaborn 그림과 조금 다를 수 있음). 70쪽 사분위수 QR 자료(정규 분포 σ 그림)는 「이상치 확인」 측주 한 줄로만. 이상치 찾기 함수(교과서 소스 파일의 `outlier()`)는 노트북에만 둠. tips의 5·6단계는 교과서에 「예시 답안: 소스 파일 참고」로만 있어 소스 파일 실행 결과를 보여 줌.

**지어낸 것(예시 표시함)** — 도입 투표의 설문 상황(교과서 68쪽 설문 예를 빌림), 01의 「중앙값으로 대체」 선택지(교과서는 「특정 값」이라고만 함 → 평균·중앙값 둘을 예로 둠).

**확인할 점(교과서 모호한 곳)**
- 68쪽 측주(결측치 표기, (가)·(나) 주의점), 69쪽 「이상치 확인」, 73쪽 「여기서 잠깐!」은 학생용 교과서에도 있음(검토에서 학생용 PDF로 확인) → 쪽수를 달아 씀.
- 68쪽 표 Ⅱ-4 머리글 「꽃일 길이」는 오탈자 → 「꽃잎 길이」.
- 행 삭제의 근거는 교과서 문장 그대로(「데이터의 양이 충분히 많다면 결측치가 있는 행을 제거하는 (다) 방법이 가장 적절하다」). 「30개뿐이라면」은 질문폼 1번을 위해 Iris2.csv 30행만으로 같은 방법을 해 보게 함(실제 결과: 22행, 세토사 10→5개).
- 69쪽 기초 통계량 해석의 예시 답안 「count의 개수가 다르기 때문에 편향성 측면에서 고민해야 할 요소가 있다」는 교사용 예시 답안 → 02 탐색기 아래 「생각해 보기」로만 씀.
- 70쪽 박스 플롯 해석은 꽃잎 길이(➌)에서 버지니카만 말하지만, 같은 규칙(1.5×IQR)으로 계산하면 세토사 꽃잎 길이(12개)·세토사 꽃잎 너비(0.5, 0.6)·버시컬러 꽃잎 길이(3.0)에도 이상치로 판정되는 값이 있음(그래프 눈금이 55·111 때문에 커져 그림에서는 잘 안 보임). 71쪽 `drop(index=[…])` 목록 16개는 이 값들까지 모두 모은 인덱스와 정확히 같음(직접 계산해 확인). 03 활동에서 학생이 직접 확인할 수 있게 둠(세토사 꽃잎 길이 1.0·1.9처럼 실제로 있을 법한 값도 규칙상 이상치가 됨 → 질문폼 2번 「삭제 전에 확인할 것」과 연결).
- **71쪽 `df3.drop(index=[3, 5, 6, …])` 주의**: `pd.concat`이 원래 인덱스를 유지해 Iris1 부분(0~149)과 Iris2 부분(0~29)의 인덱스가 겹침. 그래서 이 코드는 목록의 번호를 가진 행을 **두 파일에서 모두** 지워 172행 → 147행(세토사 39개)이 됨. 72쪽 히트맵 값(0.96·0.87·−0.36 등)은 바로 이 147행으로 계산한 값과 정확히 같아서 교과서 결과는 이 상태 그대로임. 화면 03에는 접어 둔 「더 알아보기」로만 알리고(종류별 개수 변화와 `ignore_index=True` 방법), 산점도·히트맵은 교과서와 같은 147행을 씀. 수업에서 다룰지 선생님 판단 필요.
- 72쪽 히트맵과 산점도에 「일련번호」가 속성처럼 들어 있음(데이터가 종류 순서로 번호가 붙어 꽃잎 속성과 상관계수가 0.7대로 나옴). 04에 「생각해 보기」로 일련번호는 꽃의 특징이 아니라는 점을 한 줄 덧붙임.
- 73쪽 문제는 「total_bill에 가장 큰 영향을 주는 핵심 속성」을 찾으라고 하지만 tip은 계산 뒤에 정해지는 값이라 상관관계가 영향(원인)을 뜻하지는 않음 → 05 메모 `tipsCause`로 생각해 보게 함.
- 질문폼 확인: 「161번 버시컬러 꽃받침 길이」(71쪽 실행 결과 일련번호 161, 15.0)와 「행 삭제 이유」(68쪽) 모두 교과서와 일치.
- 노트북은 저장소 공개 주소에서 CSV를 읽으므로 **저장소에 올라간 뒤에야 코랩에서 열림**. tips는 seaborn이 인터넷에서 받아 옴.

**검토 반영** — 05 tips를 「선택 · 과제」로 바꾸고(표지 목록·오늘 할 일·화면 제목에 표시) 퀴즈 2문항을 뺐으며, 주요 개념 정리·스스로 점검은 04 끝으로 옮김(퀴즈 13 → 11). 02 `groupby(...)['꽃받침 길이'].describe()` 아래에 69쪽 실행 결과 표를 넣어 해석과 맞춤(탐색기는 스스로 해결하기에 맞게 꽃받침 너비로 시작). 박스 플롯: 끌기 중 버튼이 떼어졌는데 pointerup을 놓친 경우(`e.buttons`가 0), `lostpointercapture`, 종류·속성 바꿀 때 끌기 상태를 풀도록 함. 고른 점이 지금 종류에 없으면 기본 점으로(조정자 수정 유지). 울타리값은 소수 넷째 자리까지(3.7875·7.2875). 「노트북 마지막 셀」 → 「노트북의 더 알아보기 셀」. 04 일련번호 설명 옆에 「종류를 가르는 근거는 산점도, 히트맵은 속성끼리의 관계」 한 줄 추가. 「지난 시간」 표현 3곳(시작, 02 생각해 보기, 03 더 알아보기)을 순서와 상관없는 말로 바꿈. 05의 isna·describe 코드와 결과는 시간 때문에 그대로 보여 줌.
