## 50분 흐름
- 도입 3분: 핵심 질문, 세 프로젝트 길 지도, `planMemo` 한 줄.
- 01 SDGs와 문제 정의 7분: 카드 세 장 뒤집기(번호 먼저 떠올리기) → 내 프로젝트 카드 → `myProblem`.
- 02 흐름도 12분: 한 프로젝트(펭귄 권장)는 필수, 나머지 둘은 선택(화면에 안내). 진행 상황은 학번별로 이 기기에 저장(새로 고쳐도 유지). 다 채운 뒤 「이 프로젝트에서 한 일」 읽기. 단계 수 비교표.
- 03 비교·편향성 10분: 분류 게임 9장(3분) → 데이터 편향성 카드 → `biasMemo`.
- 04 진로 8분: 스타트업 사례 읽기, 대화 펼쳐 보기, 역할 고르기, `careerMemo`.
- 05 정리 6분: 역량 Check → `projReflect`. 빈칸은 접어 둔 선택 활동(퀴즈와 겹침).
- 마무리 4분: 퀴즈 결과 확인 후 질문폼(질문폼은 메모를 보며 다시 씀).
- 시간이 모자라면 02는 한 프로젝트만, 05 빈칸은 건너뛰어도 된다(퀴즈와 겹침).

## 체험 위젯
1. **흐름도 완성하기**(02, lesson.js `FLOW`): 탭(프로젝트 3개) + 8칸 보드 + 카드 9장(정답 8 + 함정 1). 다음 칸에 맞는 카드만 놓이고, 틀리면 그 칸의 힌트, 함정 카드면 「왜 이 프로젝트와 맞지 않는지」 해설. 프로젝트별 진행은 학번별 키(`MK+'-flow'`)로 이 기기에 저장되어 새로 고쳐도 유지(MEMO에는 넣지 않음). 카드·탭은 `<button>` → 터치·Enter·Space 모두 됨. 카드·탭 묶음 안에서 방향키로 포커스 이동(`preventDefault`로 화면 넘김 막음). 폰 375px: 보드는 한 줄씩 쌓이는 목록, 넓은 화면은 2열.
2. **분류 게임**(03, 공용 `sorter`): 세 프로젝트 칸. 사실 9장(프로젝트마다 3장: 데이터 · 알고리즘 · 평가 지표). 시간 때문에 목표·개선 카드는 뺌(목표는 01, 개선은 02 「한 일」과 편향성 카드에서 다룸). 애매한 문장(예: 「정확도」만 있는 카드)은 넣지 않음.

## 교과서에서 애매한 점
1. 219쪽 펭귄 흐름도는 첫 칸과 둘째 칸이 모두 「펭귄 종류 데이터 수집」으로 겹쳐 있다. 강의용 PPT(218~219쪽)와 다른 두 흐름도는 둘째 칸이 「데이터 확인 및 데이터 전처리」 → 위젯은 「데이터 확인 및 데이터 전처리」로 하고 화면 안내에 적음.
2. 단계 수가 쪽마다 다르다: 174쪽 5단계(문제 정의 · 데이터 수집 및 전처리 · 기계학습 유형과 알고리즘 선정 · 모델 학습 · 성능 평가 및 수정), 180~181쪽 6단계, 191쪽 8단계(데이터 시각화 및 분석 · 수정 및 성능 개선을 따로), 203쪽 7단계. 219쪽 흐름도는 문제를 가운데 두고 8칸(모둠별 발표 포함). → 02에 「단계 수는 달라도 흐름은 같다」 비교표로 보여 줌.
3. 펭귄 프로젝트는 시각화(pairplot·히트맵)를 「데이터 전처리」 단계 안에서 했다(184~185쪽). 219쪽 흐름도는 「데이터 시각화 한 후 분석」을 따로 둠 → 흐름도 칸 설명에 「전처리하며 pairplot·히트맵」으로 적음.
4. 216쪽 회색조 모델 코드는 `classes4`에 예측을 넣고 `classes2`(숲 사진 결과)를 출력하며, 회색조로 바꾼 `read_img`는 학습 데이터에 쓰이지 않는다(33차시 확인). 화면은 코드를 싣지 않고 교과서 결과를 「소개」로만 쓰며, 회색조의 한계(진짜 산불 사진을 놓칠 수 있음)와 근본 방법을 덧붙임.
5. 185쪽 「여기서 잠깐!」은 map( )으로 숫자를 바꾸는 것을 원-핫 인코딩이라고 부르지만, map( )은 값마다 번호를 붙이는 방식이다 → 화면에서는 「범주형 값을 숫자로 바꾸기(map)」라고만 쓰고 원-핫 인코딩이라는 말은 쓰지 않음.
