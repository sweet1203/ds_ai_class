쓰기 메모 3칸(`autoVsHuman`·`openData`·`arriveWay`) + 고르기 1개(`arrivePick`). 퀴즈 10문항. 질문폼 1번 ← 01 설문 체험·04 등교 시간 고르기·`arriveWay`, 2번 ← 03 분류 게임·`openData`, 3번 ← 02 분류 게임·`autoVsHuman`.

**50분 흐름** — 도입(4분) 데이터가 가장 큰 영향을 준다는 말, 생각 열기 → 01(10분) 수동 수집 읽기, 온라인 설문에 답하고 표가 바로 바뀌는 것 확인 → 02(12분) 자동 수집 읽기, 분류 게임, 소스 코드와 결과 그래프는 선생님과 함께(코랩 실행은 선택), 메모 → **03(26분 무렵 시작, 9분)** 공유 사이트 하나를 열어 보고 공개 분류 게임, 메모 → 04(7분) 등교 시간 조사 방법 고르기, 메모 → 마무리(8분) 퀴즈 결과 확인 후 질문폼.

**줄인 것** — 64~65쪽(데이터 편향성, 붓꽃 데이터 수집 실습)은 다음 수업으로 넘김(시작 화면 핵심 요소에서 「데이터 편향성은 64쪽에서 배워요」만). 공유 사이트 실습(파일 내려받아 열어 보기)은 링크만 두고 시간이 남을 때. 코랩 실행은 선택 활동(Google Trends 접속이 막히면 실패할 수 있어 화면에 저장된 결과를 그래프로 보여 줌).

**확인할 점(교과서 모호한 부분)**
- 학생용 교과서 확인 결과(검토): 62쪽 리커트 척도법·「여기서 잠깐!」, 63쪽 사물 인터넷·센서 측정(온도계 = 수동)은 학생 교과서에도 있음 → 쪽수를 달아 인용(퀴즈 2-2 해설에 63쪽). 63쪽 지도 TIP(여러 방법을 함께 쓸 수 있음, 짧은 시간엔 공유 사이트)만 교사용이라 04에서 「더 알아보기」로 둠.
- 63쪽 QR 「웹크롤링」 소스 코드는 실제로 웹 페이지를 돌아다니는 크롤러가 아니라 pytrends(구글 트렌드 비공식 라이브러리)로 「독감」 검색 관심도를 가져오는 코드임 → 화면에서는 「인터넷의 검색어 데이터를 코드로 자동으로 모으는 예」로 설명하고, 웹 크롤러 동작은 63쪽 그림(링크 방문 → 인덱싱 → 데이터베이스 저장)으로 따로 보여 줌. 노트북 마크다운의 `h1='ko'`는 코드의 `hl`의 오타로 보이나 원본 그대로 둠.
- 코랩에서 pytrends가 지금도 동작하는지는 확인하지 못함(구글 쪽 변경·요청 제한으로 오류가 날 수 있음). 화면 그래프는 노트북에 저장된 실행 결과(2023년 52주) 그대로이고, 값은 기간 중 가장 많이 검색된 주를 100으로 둔 상대값(구글 트렌드의 방식 — 더 알아보기).
- 63쪽 「센서 측정」 설명처럼 센서를 써도 사람이 직접 재면 수동이라는 구분은 지도 TIP에 강조되어 있어 분류 게임 해설에 반영함.
- 01 설문 체험의 문항과 예시 응답 6줄, 03 공개 분류 게임 7문장, 04 등교 시간 풀이(얻기 쉬운 것·어려운 것)는 모두 교과서에 없는 예시. 개인 정보와 공개의 문제는 62~63쪽에 직접 나오지 않으므로(질문폼 2번이 묻는 내용) 03에서 예시로만 다룸.
- 03 사이트 주소는 교과서 63쪽 표의 주소를 링크로만 씀(화면 글자에는 주소를 쓰지 않음).
